## 2. 页面上有什么

### 2.1 文章列表（AdmContent）

- 页头：标题「内容管理」，右侧【新建文章】（`content.article`）。页签「文章 / 协议 / 字典与文案键」。
- 筛选：「分类」（全部 / 帮助 / 规则 / 公告 / 协议，对应 `category`，枚举 `ArticleCategory`）、「最新版本状态」（全部 / 草稿 / 已发布 / 已下线，对应 `status`，枚举 `ArticleVersionStatus`，筛的是**最新版本行**的状态）；【查询】【重置】。没有关键词搜索（契约没有，见 §7 P-05）。
- 说明条：版本怎么算、「当前版本」是什么、协议文章只读、保存会做检查（出处见 §5）。
- 表格（按 `updated_at` 新的在前，`page` / `page_size`，每页 20）：

| 列 | 契约字段 | 画法 |
| --- | --- | --- |
| 标题 | `title`（最新版本行的标题） | 文字 |
| 分类 | `category` | 中性标签；中文名见 §7 P-10 |
| 帮助小节 | `help_section`、`faq_rank`（只有帮助分类且最新行设了才有） | 小节名；有排序时下面一行「常见问题排序 N」；没有写「—」 |
| 最新版本 | `latest_version`、`latest_status` | 「vN 草稿」（钟表）/「vN 已发布」（对勾）/「vN 已下线」（灰）；`latest_status=published` 但 `current_version` 为空或小于 `latest_version` 时画「vN 定时发布」+「未到生效时间，按未发布计」 |
| 当前版本（线上） | `current_version`、`published_at` | 「vN」+「发布于 …」；为空时「无」+「用户端看不到这篇」 |
| 最近更新 | `updated_at` | 时间 |
| 操作 | — | 帮助 / 规则 / 公告：【编辑】；协议：【查看】+「只读 · 在「协议」页签发布」 |

- `article_id` 是行键，`row_version` 不显示（它只在详情里作写操作的核对值）。
- 协议分类的【查看】：用 `adminGetArticle` 打开只读的文章详情（不显示保存、发布、下线按钮）；只有同时有 `content.agreement` 的账号，页头才多一个「到「协议」页签查看版本」的链接（默认画法，见 §7 P-15）。
- 分页：「共 N 条」+ 页码 + 「20 条/页」。

### 2.2 文章详情 / 编辑（AdmContentEdit）

- 页头：【‹ 返回文章列表】、「编辑文章」、状态标签三个：「v{最新} {状态}」「线上 v{当前}」（无则「线上 无」）、「已保存 {时间}」或「有未保存的修改」；右侧【整篇下线】【保存草稿】【发布 vN】。
  - 【发布 vN】只在最新版本是草稿、且没有未保存的修改时可点（契约：只能发布最新且为草稿的版本）。
  - 【整篇下线】在没有已发布版本时不可点（契约：没有已发布版本 → 20001 `[article_id]`）。
- 左栏：标题输入框（1–100 字，`title`）；正文富文本（`body`，tiptap JSON 字符串）。**编辑器只画外观**：工具栏（正文、标题 1–3、加粗、斜体、无序 / 有序列表、引用、分隔线、换行、链接）+ 正文区，不画图片、配置变量、预览等按钮。正文下方提示链接要求（出处：契约保存检查）。
- 右栏「文章信息」：分类（只读，建文章时定）、文章 ID（`article_id`）；帮助分类另有「帮助小节」下拉（`help_section`，枚举 `ArticleHelpSection` 六个值）和「常见问题排序」（`faq_rank`，1–999，可空）；公告分类另有「用户可以关闭这条公告」（`notice_closable`）和「失效时刻」（`notice_end_at`，不可关闭时必填）。
- 右栏「版本」：`versions[]` 新的在前，每行「vN + 状态标签 +（当前版本）+ 保存于 / 发布于 / 定时 … 生效」+【查看】（只读载入该版本，不覆盖编辑中的内容）。
- 写操作都带 `expected_row_version` = 打开时读到的 `row_version`；保存、发布、下线成功后用响应里的整篇文章刷新页面和新的 `row_version`。

### 2.3 新建文章（AdmContentNew）

- 左栏「基本信息」：分类单选（帮助 / 规则 / 公告；不含协议）、标题；按分类出现帮助字段或「公告设置」。右栏正文编辑器（外观同上）。
- 页头【取消】【创建草稿】；说明条「创建后是第 1 版草稿，不会发布」。
- 打开新建页时前端生成一次 `article_id`（小写标准 UUIDv7），这一页内的每次重试都复用它（契约 `adminCreateArticle`）。
- 切换分类时清掉不属于该分类的字段（非帮助不带 `help_section` / `faq_rank`，否则 20001）。

### 2.4 发布弹窗（AdmContentPublish）

- 键值：文章、本次发布「vN（最新草稿）」、现在线上「vM · 时间 发布」。
- 「生效时间」单选：立即发布（不带 `published_at`，按服务器时间）/ 定时发布（带 `published_at`）；定时时出现「生效时刻」，不能早于现在。
- 说明条：只能发布最新草稿、会再做一遍保存检查、旧的已发布版本不会自动下线。
- 【取消】【确认发布】。请求：`version`、`published_at`（可选）、`expected_row_version`。

### 2.5 整篇下线弹窗（AdmContentOffline）

- 键值：文章、分类、将下线的版本。
- 后果：所有已发布版本（含未到时间的定时版本）改为已下线；草稿不动——有草稿时写「草稿 vN 不受影响，之后可以发布」，没有草稿时写「这篇没有草稿。要重新上线，先保存一个新草稿再发布」；公告的下线时刻记为失效时刻；写入操作日志。
- 【取消】【确认下线】。请求：`expected_row_version`。

### 2.6 协议版本列表（AdmAgreements）

- 页头「内容管理」，页签「协议」，**不设页头发布按钮**（不知道要发哪一类）。
- 筛选：「协议类型」（全部 / 隐私政策 / 用户协议 / 劳务协议 / SDK 清单 / 个人信息收集清单，`type`，枚举 `AgreementType` 五个值）。
- 说明条：发布即定版、版本号由服务端生成、每次发布要权限点 + 动态码 + 法务确认三项、最低版本的后果、SDK 清单与个人信息收集清单只作公示（出处见 §5）。
- 表格（按 `published_at` 新的在前，分页同文章）：

| 列 | 契约字段 | 画法 |
| --- | --- | --- |
| 协议 | `type` | 中文名 + 编码；每类最新一行加「最新」标 |
| 版本 | `version` | vN |
| 最低版本 | `min_version` | vN |
| 需重签 | `requires_resign` | 是：警示标签「需重签」；否：「—」 |
| 法务确认 | `legal_confirmed_by`、`legal_confirm_note` | 确认人 + 说明 |
| 发布时间 | `published_at` | 时间 |
| 正文摘要 | `text_sha256` | 前 12 位 |
| 操作 | — | 【查看正文】；每类最新一行另有【发布新版本】（盾牌） |

- 列表不显示 `article_id`、`article_version`、`url`、`published_by`，放在详情抽屉里。
- 「最新」标与【发布新版本】：列表按 `published_at` 全局倒序，第 1 页里每类第一次出现的行就是该类最新版本；按 `type` 筛选时第 1 页第 1 行就是最新。第 2 页起（不按类型筛选时）判断不出某类的最新版本，默认这几页不画「最新」标与【发布新版本】（§7 P-19）。
- 点【发布新版本】后，发布页**不用列表行的数据**：重新用 `adminListAgreements`（`type` = 该类型，`page_size=1`）取第 1 条作 `expected_version`（没有则 0），再用 `adminGetAgreementVersion` 载入它的正文作底稿。
- 还没有任何版本的类型不会出现在列表里；按该类型筛选后是空列表，空态里给【发布第一版】（AdmAgreementsEmpty）。

### 2.7 协议版本详情抽屉（AdmAgreementVersion）

- 标题「{类型中文名} vN」，副标题「已发布 · 只读」。
- 键值：协议（中文名 + `type`）、版本、最低版本、需重签、发布时间、发布人（`published_by`，只有账号 ID，见 §7 P-08）、正文文章（`article_id` + 「文章第 `article_version` 版」）、正文 sha256（`text_sha256`）、全文地址（`url`）。
- 「法务确认」：确认人、说明。「正文」：`title` + `body` 只读渲染。
- 【打开全文地址】（新窗口打开 `url`）【关闭】。
- 读取出错时抽屉内显示出错态（`error.50001` +【重新加载】）；版本不存在见 AdmAgreementVersionNotFound。

### 2.8 发布协议新版本（AdmAgreementPublish）

- 页头「发布{类型}新版本」，右侧【取消】【发布 vN】（盾牌）。
- 左栏「协议正文」：标题（`title`，1–100 字）、正文编辑器（`body`，外观同文章；打开时用 `adminGetAgreementVersion` 载入该类型当前最新版本正文作底稿；第一版没有底稿）。
- 右栏「发布设置」：协议类型（只读）、本次版本「vN（服务端生成）」、当前最新「vM · 时间」或「无」；最低版本（`min_version`，提示允许范围「不低于当前版本的最低版本，不高于本次版本」）；「本版需要用户重新签署」（`requires_resign`）。
  - SDK 清单与个人信息收集清单：最低版本固定等于本次版本、置灰；需重签固定不勾、置灰（契约：这两类不参与同意，D10-465）。
  - 「需重签」提示按类型分：劳务协议写「勾选后，已签旧版本的用户下次提现前要重新签署」（BR-WDR-31）；隐私政策、用户协议对用户有什么影响规则没写，提示用方括号占位（§7 P-09）。
  - 底稿读不出来时整页换成出错态 +【重新加载】，发布按钮置灰，不提供空白底稿发布（AdmAgreementPublishLoadError）。第一版本来就没有底稿，不算出错。
- 「法务确认（每次发布都要填）」：法务确认人（`legal_confirmed_by`，≤64 字）、确认说明（`legal_confirm_note`，≤500 字）、确认日期（`legal_confirmed_on`）。三项都必填（契约请求体 required）。
- 所需权限行：`content.agreement` · 动态码。
- 隐藏字段 `expected_version` = 打开发布页时该类型的最新版本号（没有则 0）。
- 契约请求体就是这八个字段；**旧稿画的字段与契约一致，没有多画或少画**。

## 3. 操作与接口

| 操作 | operationId 与方法路径 | 权限点 | 二次验证 | 成功后 | 失败码与显示 |
| --- | --- | --- | --- | --- | --- |
| 文章列表 | `adminListArticles` GET /admin/v1/articles | `content.article` | 不要 | 显示表格 | 10001 跳登录；10403 无权限空态；20001（`page_size`，不应出现）；429 / 5xx / 无响应见 §4 |
| 打开文章详情 | `adminGetArticle` GET /admin/v1/articles/{article_id} | `content.article` | 不要 | 显示编辑页（全部版本含正文） | 30701 文章不存在空态（AdmContentNotFound）；10001；10403 |
| 新建文章 | `adminCreateArticle` POST /admin/v1/articles | `content.article` | 不要 | 打开新文章的编辑页（v1 草稿） | 20001 字段 / 命中词 / 正文路径（同 AdmContentEditInvalid）；20001 `[article_id]`、`[category]`（不应出现）；20902 = 这个 ID 已建过 → 读回并打开编辑页，不提示冲突；10001；10403 |
| 保存草稿 | `adminSaveArticleDraft` PUT /admin/v1/articles/{article_id}/draft | `content.article` | 不要 | 新增一个草稿版本，页面按响应刷新 | 20001（AdmContentEditInvalid）；20001 `[category]`（不应出现）；20902（AdmContentConflict）；30701；10001；10403 |
| 发布（立即 / 定时） | `adminPublishArticle` POST /admin/v1/articles/{article_id}/publish | `content.article` | 不要 | 编辑页按响应刷新，提示已发布 / 已定时发布（AdmContentPublished） | 20001 `[published_at]`（AdmContentPublishInvalid）；20001 `[version]`；20001 保存检查；20001 `[category]`；20902；30701；10001；10403 |
| 整篇下线 | `adminOfflineArticle` POST /admin/v1/articles/{article_id}/offline | `content.article` | 不要 | 编辑页按响应刷新，全部已发布版本变「已下线」 | 20001 `[article_id]`（已没有已发布版本）；20001 `[category]`；20902；30701；10001；10403 |
| 协议版本列表 | `adminListAgreements` GET /admin/v1/agreements | `content.agreement` | 不要 | 显示表格 | 10001；10403（AdmAgreementNoPerm）；20001（`page_size`，不应出现） |
| 协议版本详情 / 发布页底稿 | `adminGetAgreementVersion` GET /admin/v1/agreements/{type}/versions/{version} | `content.agreement` | 不要 | 打开详情抽屉 / 载入底稿 | 30701（AdmAgreementVersionNotFound）；20001 `[type]`；10001；10403 |
| 发布协议新版本 | `adminPublishAgreementVersion` POST /admin/v1/agreements/{type}/versions | `content.agreement` | 动态码，每次发布都要 | 回协议列表，提示已发布（AdmAgreementPublished） | 10003 `tier=totp` → 动态码弹窗后重发（AdmAgreementPublishStepUp）；20001 `[min_version]`（AdmAgreementPublishInvalid，服务端兜底）、`[requires_resign]`、法务三项、`[body]`；20902 `resource=agreement`：首次提交 → AdmAgreementPublishConflict，结果未知后重试 → AdmAgreementPublishUnknownDone；10001；10403 |

每个操作的所有返回码怎么显示，画在两张「返回码一览」里：AdmContentErrors（文章 6 个操作）、AdmAgreementErrors（协议 3 个操作）。所有操作都可能收到 429（42901，按 `Retry-After` 置灰按钮，缺省 5 秒）和 5xx（50001）。

## 4. 各状态怎么显示

| 状态 | 文章 | 协议 |
| --- | --- | --- |
| 加载中 | 列表区换成表格骨架，筛选与页签照常可用（AdmContentLoading）；详情页加载同理（骨架按两栏布局，不另画） | 同左（AdmAgreementsLoading）；详情抽屉加载时抽屉内骨架（不另画） |
| 空 | 筛选无结果：「没有符合条件的文章」+ 当前筛选 +【重置筛选】（AdmContentEmpty）。不加筛选时，只要发布过任何协议，列表里就至少有协议文章，所以「一篇都没有」只在系统刚上线时出现，写法同上、按钮换【新建文章】（不另画） | 按类型筛选、该类型还没有版本：「X 还没有发布过版本」+【重置筛选】【发布第一版】（AdmAgreementsEmpty）；第一版发布页见 AdmAgreementPublishFirst（本次版本 v1、当前最新「无」、没有底稿、`expected_version=0`） |
| 无权限（10403） | 两个权限点都没有：整页空态，侧栏不显示「内容管理」，按钮回到该账号能进的第一页（AdmContentNoPerm，查询小狸）。有协议权限而没有文章权限的账号同理只是不显示「文章」页签（样例里没有这种账号，不另画） | 没有 `content.agreement`：「协议」页签不显示；从链接打开显示空态（AdmAgreementNoPerm，运营小凑） |

**结果未知**（请求发出后网络中断、超时或响应读不出）：对话框或页面保持打开并锁定，输入置灰、保留已填内容；顶部警告条「结果未知：没有收到服务器的回应」；底部（整页时在页头）只有【重试】【去列表核对】；没有【取消】、没有右上角关闭，整页时【‹ 返回文章列表】与版本【查看】也置灰；不自动重试。【重试】把同一个请求原样重发（同样的内容、本次提交时的核对版本）；【去列表核对】关闭并回列表重新读取。

通用原则：凡是「结果未知后重试」收到的冲突类回应（20902，以及发布时的 20001 `[version]`、下线时的 20001 `[article_id]`），第一次多半已经生效，所以**不显示成「没有生效」，也不留下可以再提交同一内容的入口**（保存草稿例外：分不出最新一版是不是自己存的，见 P-17，所以编辑器内容保留、【保存草稿】仍可用，实现时建议在提示里加一句「如果最新一版就是你的，不用再保存」——这个落地状态没有单独画板，措辞草拟、并入 P-13；多存一版只是多一版重复草稿）：关闭对话框或页面，重新读取，按当前状态显示，并提示「上次的操作可能已生效，请以当前状态为准」。
