## 1. 背景

- 现状：「我的」页的分组宫格由三端写死（03 §10.2 `EntryGrid`「分组与格子由客户端固定布局」；01 §4.2 `Me` 行「固定原生布局」；07 §2「个人中心装修」P2）。加一个入口要三端各改一次并发版。
- 可以复用的通道已经在：首页配置（01 F-ADM-09）走 SDUI，`GET /v1/pages/{page_key}` 的 `page_key` 本身是参数（04 §6.2：`home` 与 `custom:*`），后台有版本、发布、灰度、回滚与草稿预览，契约已支持定时发布（04 §6.6 `pages`），后台还没做定时发布的界面。
- 缺口（assessment §一）：① section 与条目都没有起止时间，只有 `popup` 有每日次数与时段；② 后台只有整页 JSON 编辑，运营实际不会用；③ 首页与「我的」是原生页，第一次改成读下发必须发一版原生，之后增删入口才不用发版。

## 2. 决定

### 2.1 机制：复用首页配置的 SDUI 通道

- 不另起一套运营位表与接口。**位置** = `page_key` + 页内 section id；本批新增 `page_key`：`me`、`search`；专题页用已有的 `custom:<slug>`。**内容** = 已注册的 section 类型（03 §6.3 卡片注册表），新类型按「注册 type 与 props schema → 三端渲染器 → golden 样例」的既有流程加。
- 版本、发布、灰度、回滚、草稿预览照首页配置现有做法；后台补定时发布的界面（契约已有）。
- 后台把「首页配置」扩为「运营位」页：按位置列出，每个位置一张表单（不碰 JSON），保存仍走现有版本与发布接口。
- 契约形状（字段名、枚举）以代码仓库 `contracts/` 为准；本记录与 04 里出现的 `start_at` / `end_at`、`float_button`、`splash`、`more_services` 等都是建议名，以契约线定稿为准。

## 7. 恢复方式

- 关掉下发即回落内置布局：把 `me` 页的 `more_services` 下线或回滚到空版本 → 客户端回落内置的默认格子；`search` 页同理只是不出置顶位；首页悬浮按钮、开屏图下线即不出现。回滚沿用页面配置现有的回滚（04 §3.2 `pages` / `page_versions`），不需要发版。
- 规则需要整体撤回时：BR-TEXT-28～30 按 08 README §0.2 作废保留编号；范围按 00 §4 改回原阶段。已经发出的原生版本保留读下发能力，没有配置时与旧版表现一致。
