# 2026-11-28 CSB-09 加系统分享接收入口

**类别**：00 §8 第 ② 类——修改 03 §4.8 安全基线里「不可豁免」的 CSB-09（入口组件最小化）。不改金额口径、订单归属、用户授权边界，也不改对外承诺；系统分享面板接收这项功能的开放阶段仍按 00 D21（P1），本次不改。

**批准**：负责人 2026-11-28 12:10 在编排会话里回复「现在装，护栏甲，二次验证甲，分享甲，推广位甲」，其中「分享甲」就是本条（编排裁定 D10-3665 / D10-3700 ④）。本规划 PR 由负责人合并。

## 1. 变更内容与理由

- **内容**：CSB-09 原文规定 Android 只能导出「启动入口」和「声明了深链的入口组件」，鸿蒙只有入口 Ability 能声明深链。现在加一类**系统分享接收入口**，允许导出或声明，但有四条限制：
  1. 只收系统分享传来的文本与图片（Android `ACTION_SEND`、鸿蒙分享接收）；
  2. 不接受路由名、URL 或路由参数作为导航指令；
  3. 收到的内容按剪贴板 / 粘贴同一套不可信输入处理，只交 `POST /v1/inputs/parse` 识别；
  4. 这项功能何时对用户开放，仍按 00 D21（P1）。
- **理由**：Android 代码里已经有分享接收组件 `ShareReceiverActivity`（只带 `ACTION_SEND`）。CT-17l 契约评审 r1 指出，把它登进 CSB-09 允许清单与规划原文冲突。可选的路有两条：把它从允许清单去掉，等 CSB-09 检查启用时再挡构建、到 P1 再处理；或者现在就在规则里写清这一类入口和它的限制。负责人选了后者。
- **代价**：多一个对外入口。它只收文本或图片、不做导航，内容按不可信输入只交给服务端识别，风险与剪贴板 / 粘贴相同，没有新增权限面。

## 2. 涉及的规则与文档

- **03 §4.8 CSB-09**：加「系统分享接收入口」一类及上面四条限制。
- **03 §4.4**：入口组件一段补同一句的指针。
- **08 业务规则**：不改。分享进来的内容与剪贴板 / 粘贴同一套不可信输入，按现有规则处理，不新增 BR。
- **00 D21**：不改，功能开放阶段仍为 P1。

## 3. 受影响的页面、接口与代码

- **契约仓库**：`specs/client-security-baseline.yaml` 的 CSB-09 允许清单可以登记分享接收组件。由 be 线 CT-17l 在本 PR 合并后的契约评审 r2 中按本条写。
- **Android**：`com.couli.app.clipboard.ShareReceiverActivity` 照现状保留，须满足上面四条限制。CSB-09 检查启用时，以允许清单为准。
- **鸿蒙**：以后的分享接收（P1）按同一条执行。
- **iOS**：不受影响。iOS 的分享扩展是独立扩展，不属于 CSB-09 的组件导出范围。
- **接口**：不改。分享内容仍走 `POST /v1/inputs/parse`。

## 4. 验收要点

- 契约 `specs/client-security-baseline.yaml` 的 CSB-09 允许清单登记了分享接收组件，并写明用途；没有登记的导出组件仍判失败。
- Android 合并后的清单里，分享接收组件的 intent-filter 只有 `ACTION_SEND`（文本 / 图片）。组件不读取任何路由名、URL 或路由参数作为导航指令；收到的内容只交给识别接口。

## 5. 恢复方式

若要收回：从 03 CSB-09 删掉「系统分享接收入口」这一类，并从契约允许清单去掉该组件；Android 的分享接收组件改为不导出或删除，等 P1 再按当时的规则加回。这样做不涉及数据迁移，也不改接口。
