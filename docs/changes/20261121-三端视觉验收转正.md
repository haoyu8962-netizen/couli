## 1. 试行结论（按试行记录 §3 的成败判定：成）

试行记录 §3 的判定是两条满足其一即「成」：
- 找到至少一处现有自动断言没拦住的局部缺陷；
- 或者确认鸿蒙人工核对一轮半天内能做完。

这次两条都满足：

| 判定条件 | 结果 |
| --- | --- |
| 找到现有自动断言没拦住的缺陷 | 鸿蒙登录页在 200% 字号、整窗宽下，键盘弹起后【获取验证码】被盖住：键盘以上看不到按钮，页面不上推、也滚不到。100% 时余量只有 14 px，320 宽时 0 px。编排已开单 FU-LOGIN-KEYBOARD-AVOID（上线前必修），iOS、安卓各自核同一页 |
| 鸿蒙人工核对一轮的用时 | 首跑截图 352 s，补拍 463 s，核图约 10 分钟，合计约 24 分钟，远在半天以内 |
| 鸿蒙 ProductCard、AmountGrid 两个试点组件 | 浅 / 深 × 默认 / 200% 共 8 格，四处关键局部全部「通过」 |

AmountGrid 的 200% 是页内【Font 2.0x】缩放，不是启动参数。两种口径的字高对照没量成，编排按源码判定一致：两条路都调用同一个 `setFontSizeScale`（D10-2378）。

试行里看到、转正时一并处理的几点：
1. **两份试点报告整份仍是「待验」**：
   - 原因是 iOS、安卓按试行安排不补测试、没填行。
   - 盘点显示两端已有不少金额不裁切、不重叠的自动断言，但深色格和最长内容格有缺：
     - iOS：ProductCard、AmountGrid 的组件快照写死浅色；
     - 安卓：ProductCard 缺浅色默认的最长组合，深色格也缺；AmountGrid 四格都没有最长金额用例。
   - 正式做法因此允许「有等价自动断言的格子用断言作证据」，没有的格子照样截图，见下文第 2 节第 3 点。
2. 键盘遮挡这一类问题，原有的关键局部清单没有点名。登录页的问题是专门安排了键盘核查才查出来的。所以正式做法增补一条通用核对项，见第 2 节第 4 点。
3. 键盘弹起的截图可能带出剪贴板建议栏、输入法候选等内容。试行里原图只放在私有目录，本线只看遮罩副本。正式做法写成规定，见第 2 节第 5 点。

## 2. 正式做法

规定只写在 规划/05 QA-11 验收列与报告表模板里，本节是摘要。

1. **适用范围**：三端（iOS、安卓、鸿蒙）每个新页面、新组件合并前。这是合并前的验收项，由实现方按端填表、评审方核表，**不是 CI 门禁**；不加 CI 检查、不写钩子。已合并的页面在 QA-11 逐页走查时照同一口径核。
2. **矩阵**：
   - 四处关键局部：价格行、返利标签、主按钮、金额格；
   - 乘以：浅 / 深 × 默认 / 最大字号 × 最长内容；
   - 填 `docs/templates/visual-acceptance-report.md`；对象没有某处局部的，那一格写「不涉及」；
   - 否决口径与有意裁切的排除沿用试行：即使整图差异在阈值内，四处有非设计意图的截断或重叠即退回；`design/ui-rules/README.md` §3.8 的框内横滑、末端渐隐不算缺陷。
3. **证据**：
   - iOS、安卓：有等价自动断言的格子可以用断言作证据，表里写明测试名与所在提交；
   - 断言没覆盖的格子（目前多是深色与最长内容）照样要截图；
   - 鸿蒙：没有等价断言的格子用设备截图加人工核对。
4. **增补通用核对项**：凡是「输入框 + 底部主按钮」的页面，在最大字号与最小宽度（320 宽）下键盘弹起时，主按钮必须整块可见、可点。结论写在报告表的「主按钮」格，备注写余量。
5. **键盘截图**：带键盘的截图只保留遮罩副本入库（至少遮住键盘区与剪贴板建议栏），原图不入库。
6. **不变的**：
   - 差异台账底线（DSX-09 行：金额、返利、主按钮的截断或重叠不得登记为已知例外，负责人确认）；
   - 三端各自出基准、不跨端对图（00 D37、03 §11）；
   - UI 修复轮次上限（规划/11 §2.5）；
   - 容差表与完整规范包仍归 DSX-09。
