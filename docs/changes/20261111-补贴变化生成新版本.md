## 1. 问题

B1-18c 让淘宝适配器输出了补贴类佣金之后，核查发现快照与订单会对不上：

1. 补贴单独变了、有效联盟佣金 N 没变时，不产生新版本（BR-CALC-15 原文「只有新 N 与已存值不同时才 +1」）。快照四段金额里含补贴的三段（联盟佣金总额、基数前扣除、平台预估利润）停在旧补贴。
2. 之后 N 变化写新版本时，实现沿用首次快照冻结的补贴，不取订单当时的补贴，与 BR-CALC-27「按该版本落四段金额」不符。
3. 例：快照时 n_base 800、补贴 200，v1 联盟佣金总额 1000。只有补贴变成 350，订单列是 350，快照仍是 1000。N 再变成 900，v2 写成 900 + 200 = 1100，按订单当时的值应为 1250。

眼下没有实际影响：R1 联盟对账与毛利报表都没实现，入账开关默认关。但 R1 以后读快照会和联盟总额对不上，报出假的差错单。

## 3. 回写内容

- **BR-CALC-27**（细则）：加「仅补贴变化的版本」一段——各方份额与上一版本逐项相同，只重算含补贴的三段，不改状态、不写分录、不发通知、不生成补差候选、不触发扣回；补贴空值与 0 视为相同，报文的平台更新时间早于订单当前记录时不写（时间相等而内容不同照常处理），同一报文重投不写。每个版本的四段金额取写入时订单的补贴。合计表加 `subsidy_commission_fen` 一列记该版本所用补贴。补一个算例。
- **BR-FUND-09**（细则「正差批准的默认」⑤）：正差候选按结算记录序号与各受益人差额判重，不按版本号，取代 D10-780 的「换版本就把待审候选作废重建」。差额没变时待审候选不动、已驳回的不重新生成；差额变了的仍照原做法作废重建。批准时不再因为版本号与候选生成时不同而作废，逐单重算、seq 变即作废、重算为 0 记已批准这些原有处理（D10-770）不变。这样才符合 BR-CALC-23「驳回则不记账并保留候选与驳回理由」。BR-CALC-23 细则只加一个指针。
- **BR-CALC-22**（细则）：试算后、发布前，样本订单只因补贴变化写了新版本，不算样本变化，不要求重跑试算。

## 6. 验收

规则测试钉住：仅补贴变化 → 版本 +1、各方份额逐项相同、含补贴的三段按新补贴、无通知无分录；空值与 0 不触发；更新时间早于当前记录的旧报文不触发，时间相等而补贴不同的照常触发；同一报文重投不触发；随后 N 变化的新版本取当时的补贴；维权重定价不因此多推一次版本；待审候选不作废、已驳回候选不复活；试算样本校验不因此失败。
