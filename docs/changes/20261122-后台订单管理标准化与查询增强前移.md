**来源**：负责人提供的后台订单页调研（参考材料，不进本仓库）；对照的是代码仓库主干 `33186e29c` 的 `apps/admin/src/pages/orders/`、`contracts/openapi.yaml` 订单相关路径与 `ops/tasks` 台账。

## 1. 现状与缺口

后台已有：全平台一张订单总表（平台是筛选项）、平台状态 / 返利状态 / 标记 / 订单号 / 用户 / 付款时间筛选、订单详情（状态卡、状态历史、分佣快照、link_log）、手动同步与同步记录（F1-07e、F1-07eb 已合并）。暂扣 / 解除暂扣 / 未归因订单指派的后端接口已上线（adminHoldOrder、adminUnholdOrder、adminReassignOrder），后台页面还没有入口。

缺：列表上方的汇总指标与带数量的状态页签；列显示配置、页大小可选、固定表头；订单号 / UID / 商品 ID 复制；商品与会员信息成块展示；详情抽屉与返回后筛选保留；常驻同步状态；商品 ID、单号后六位、店铺、标题、佣金比例与预估佣金区间、确认收货时间筛选；同条件导出。后台 23 个页面目录各自写表格，没有通用列表组件。

## 2. 决定

1. **一套标准，九个平台共用**：订单列表、详情、筛选、写操作入口对 PlatformCode 的全部平台用同一套页面与组件；平台之间的差别（额外列、详情平台字段、支持的筛选项、能否按单号同步）只写在一份平台配置里，页面代码不按平台分支；新平台接入只加配置。平台字段的取值与含义以 08、09 为准，09 未验证的字段不进配置。
2. **先做后台通用列表组件**（表格与列配置、筛选栏与 URL 同步、状态页签、指标卡、复制、金额、状态标签、说明问号、商品块、会员块、详情抽屉），订单页第一个用；其他页面以后逐步换，不一次改全。
3. **F-ADM-25 前移到本期**：查询增强筛选、状态计数、汇总指标、同条件导出（接现有异步导出，留存仍按 BR-ID-30）。汇总只对已存字段求和计数（付款金额、子单数、预估佣金、分佣快照里的平台留存、去重下单人、按平台状态分的有效口径），不新造金额算法；要别的算法属资金口径，另请负责人定。
4. **不做**（沿现行规则）：把已归属订单改给他人（BR-FUND-01 R14 自 2026-10-18 不开放，BR-ATTR-31）；按当前比例重新分佣（会改分账快照）；手动锁定 / 解锁（「已锁定」「归属已锁定」是展示标记，F-ADM-05）；向推广者提供团队订单（F-ADM-25 原文）。

## 4. 验收

- 九个平台的订单都在同一页面显示，切换平台只改变配置里列出的列、字段与筛选项；代码检索不到按平台写死的分支。
- 列配置、页大小、筛选条件在刷新与返回列表后保留；读不到本地存储时用默认列，页面照常可用。
- 汇总卡与状态计数的数字与同条件列表一致；点汇总卡写入对应筛选。
- 导出与列表同条件，经异步导出页取文件，留存按 BR-ID-30。
- 暂扣、解除暂扣、未归因指派按权限点显示、走二次验证；已归属订单不出现改给他人的入口。

## 5. 恢复方式

F-ADM-25 退回 P1：恢复 01 F-ADM-25 的阶段列、00 §4 与 07 的候选清单、05 §8.1 那一行，撤下 F1-07ef；F1-07ec、F1-07ed、F1-07ee 只用现有接口，可单独保留。

## 6. 2026-11-24 补充：订单列表默认列、详情抽屉入口与同步状态条的口径（F1-07edb）

来源：负责人 2026-11-23 对订单页画稿的意见，编排裁定 D10-2734、D10-2735、D10-2748 落定，2026-11-24 D10-2794 回写（00 §8 第 ① 类：补充界面口径，不改已确认决定、不涉及金额与归属）。此前任务书里「默认显示全部列（十一列）」「列表初次加载不请求同步接口」两处写法由本节取代。

- 默认列：订单列表默认显示 8 列（订单号、平台、商品、用户、付款时间、付款金额、联盟佣金、返利状态）与【操作】；平台状态、标记默认隐藏，可在列设置里打开。读不到本地存储时用这组默认列。
- 详情入口：行内【查看】打开详情抽屉，带深链参数可直接打开；关闭后回到原位置，筛选与页码不丢。【详情】仍进整页 `/orders/<id>`。
- 同步状态条：列表常驻显示最近一次同步的状态，初次加载用现有同步记录接口取最近一条（`page=1`、`page_size=1`）；取数失败只在状态条提示，不影响列表。
