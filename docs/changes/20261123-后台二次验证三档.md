## 1. 决定

1. **第二因子**：后台登录 = 账号密码 + 第二因子 + IP 白名单。第二因子有验证器动态码（TOTP）与短信验证码（发到本人登记的验证手机号）两种，每个后台账号至少开启一种，可两种都开；登录与二次验证都用本人已开启的方式。原「必须 TOTP」「首次登录绑定 TOTP」改为首次登录开启第二因子（绑定验证器或登记验证手机号）。
2. **三档**：none 不验证；sudo 在本次后台会话里最近一次第二因子验证通过（含登录第二步）起 180 分钟内不重问，窗口随会话结束失效；strict 每次操作都重新验证，sudo 窗口不豁免。不再分「短信档」「动态码档」。
3. **清单**（白名单，规则与每类的风险、来源只在 08 BR-ID-34 细则维护，这里只列类别）：
   - sudo：提现审核；解除提现冻结；查看完整手机号与证件号（含全量导出）；改推广位 PID；换绑或重置联盟账号。
   - strict：执行打款；人工调账；坏账核销；改自动到账开关与上限；分配或变更权限。
   - 其余一律 none。2026-11-23 前要二次验证、现在归 none 的，服务端校验代码、契约里的标记与说明、前端弹窗一并移除，不留死代码或隐形开关；权限点、必填原因、审计照旧。
4. **防漂移**：白名单制，代理不得自行扩大或提档，增加须负责人点名；每类写明防什么风险与确认来源；代码仓库建一份二次验证机读清单（逐接口登记 sudo / strict），契约在后台操作上显式标 `x-step-up`（sudo / strict，none 不标），CI 校验服务端守卫、契约标记与清单三者一致。
5. **企业微信变更告警**：改推广位 PID、换绑或重置联盟账号成功后发企业微信变更告警。现状代码里没有这项告警（这两类变更只写审计），列为待实现。
6. 08 §14.7 审计 D「同一档位 5 分钟内免验」由本决定关闭。

## 4. 影响

- **页面**：后台各页的验证弹窗大多取消，只在 sudo（窗口过期时）与 strict（每次）出现；登录页第二步按已开启的方式输动态码或短信验证码；「我的账号」可登记验证手机号作为第二因子；首次登录可选绑定验证器或登记验证手机号；联盟账号页显示本次授权到期时间与「是否可自动续期」（§6）。设计说明 `design/specs/` 各后台页、`design/wireframes/` 的二次验证标注本 PR 未改，按 08 为准，随前端改造另行同步。
- **接口与契约**：`/admin/v1/**` 各操作显式标 `x-step-up`（sudo / strict，none 不标）；none 的操作不再校验后台验证凭证、不再返回 10003；10003 的 `data.tier` 取值改为 sudo / strict；后台验证凭证与 sudo 窗口在会话上的形状、`verify_phone_missing` 的去留、短信一支（登录第二步、首次登记）的错误 reason 由契约线随后端改造定。不新增错误码。
- **历史数据与迁移**：不涉及资金数据。已绑定 TOTP 的后台账号照常可用；已登记验证手机号的账号自动视为开着短信方式。没有任何第二因子的账号只会是未完成首次登录的新账号，按首次登录流程处理。
- **验收用例**：10 AC-S2-56、AC-S2-59 等改写后的断言；代码仓库另加 CI 一致性校验作为验收门槛（§5 第 2 项）。
- **风险**：none 档的操作只凭登录会话（会话本身已过第二因子、IP 白名单，空闲 30 分钟退出），权限点与审计不变。会话被盗用时，none 档操作可直接执行；sudo 档在窗口内也可执行。负责人接受这一取舍，以换取日常操作不被反复打断。需要注意的两处：① 关闭会解除提现冻结的差错单效果与 sudo 的「解除提现冻结」相同，但按「待定行一律 none」不验证（2026-11-20 定的动态码档随之取消），要恢复须负责人点名；② 手动打款补录、W10 未知结果认定、W11 核销会把提现定为已付或退回，三档表曾倾向并入 strict，按「待定行一律 none」不验证。

## 7. 验收与恢复方式

- **验收**：后端改造合并时，CI 的一致性校验通过（守卫、契约 `x-step-up`、机读清单三者一致）；10 AC-S2-56、AC-S2-59 改写后的断言通过：none 档操作不弹验证、照常写审计；sudo 档在登录后 180 分钟内不重问、过期后验证一次即续上，会话退出后窗口失效；strict 档每次验证，sudo 窗口内也要验证；只开短信或只开验证器的账号都能完成登录与各档验证。BR-ID-24：24 小时的授权不在授权当刻进入「即将到期」，只在剩 6 小时、1 小时时各提醒一次。
- **恢复**：要给某个操作加回二次验证，由负责人点名，回写 08 BR-ID-34 清单（写明防什么风险与确认来源），代码仓库同步机读清单与契约标记，CI 保证三处一致；整体回到两档须另写变更记录、由负责人决定。本 PR 只改文档，回退即 revert 本次提交；代码改造各自按开发线的分支回退。按小时提醒可把 `union.auth_alert_hours` 配为空数组关闭。
