## 4. BR-ID-34：strict 凭证的两处解释与支付单处置（D10-2970 第 4 条与事后确认的两处）

- **内容**：
  - 「绑定本次会话与所做的操作」= 签发时不指定操作；凭证第一次被某个 strict 操作占用时绑定到该操作，之后只能由同一操作在有效期内重试（编排裁定 D10-2900 ①）。如实写明它**不防**：同一管理员在同一会话、有效期内，为甲操作验证后把还没用过的凭证第一次用在乙操作上，不拦——这是已接受的范围，不是遗漏。
  - 凭证何时消耗：业务成功才消耗；HTTP 200 + code 0 但 outcome = rejected 属明确失败，不消耗、可在有效期内对同一操作重试；结果未知占用到过期（编排裁定 D10-2943）。
  - 支付单处置（resolveAdminPayOrder）维持 none、不做二次验证：BR-ID-34 细则「不在清单里的（none）」资金一项原已列明「支付单处置（BR-PAY-05）」，本次核对后未改。
- **涉及的 BR**：BR-ID-34 细则「strict 的验证」加两条子项、状态行注明；正文与两张清单不变。
- **受影响的页面与接口**：后台二次验证凭证的签发接口、令牌头与打款批次接口三处说明口径一致（契约单 CT-24zzv）；服务端占用记录存 operationId、消耗判定看 outcome（B1-18l）。没有新增接口与错误码。
- **验收**：签发不带操作名；首次占用后换另一操作使用被拒、同一操作有效期内可重试；outcome = rejected 后凭证仍可用于同一操作；结果未知时凭证到期前不可再用。支付单处置不弹二次验证。
- **恢复方式**：回退细则新增的两条子项；契约与实现按回退后的口径另开单。
