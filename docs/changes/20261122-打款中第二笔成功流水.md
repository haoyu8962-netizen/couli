# 2026-11-22 打款中出现第二笔成功流水（BR-WDR-23 ②′）

**类别**：00 §8 第 ② 类——改的是资金规则的执行方式：提现单还在打款中（PAYING）时，通道对账发现同一提现单的第二笔成功流水，系统先做什么、追回单什么时候出。不改金额计算、分录模板、对方科目、冻结规则与二次验证档位。负责人在对话里定，按 §8「负责人在对话中明确确认的决定可以直接回写并注明日期」回写；本 PR 仍由负责人点头合并。

## 1. 问题

BR-WDR-23 正文 ① ② 只写了内部 PAYING 时出现**一条**成功行怎么办（needs_manual=false 立即查询、为 true 只给待处置提示）；细则「确有多付」② 写「同一提现单在账单里有两条成功行 → 预填追回单」，没分内部状态。两处一起读，PAYING 单出现两条成功行时会在登记差错单的同一事务里就预填追回单，而这时主单自己到底付没付成、付了几次还没定，追回金额可能算错；不预填又没有冻结的话，会员可以继续提现。

## 2. 决定

内部 PAYING 时同一提现单出现第二条成功行（不论哪一天的账单、按 out_biz_no 还是 channel_order_id 匹配到，也不论 needs_manual）：

1. 当场照 ③ 登记通道对账差错单（channel_mismatch）、告警，并为该会员新增提现冻结（withdraw_holds，reason=recon_diff，不自动到期）。
2. 登记时**不**预填 PAYOUT_RECOVERY 追回单。
3. 主单终态由人核清后再处置（落实写法见 §3）。

只有一条成功行的，照现行 ① ②。

## 3. 编排的落实写法（负责人可推翻）

| # | 写法 | 理由 |
| --- | --- | --- |
| 1 | 「人工核清主单终态」落为：该单置 needs_manual=true（已为 true 的不变），只能经 BR-WDR-15 的 W10 由人凭凭证定终态；W10 的凭证与判定条件不变 | 用现有机制，不另造流程。不置的话，needs_manual=false 的单会被自动查询直接 W5 定终态，不是「人工核清」 |
| 2 | 「再处置」落为：W10 定下终态的同一事务内，系统按细则「确有多付」判定并预填待批追回单（用户取自该提现单），财务核对账单后批准（BR-FUND-24 ⑨，方案 B 不变） | 通道对账差错单不受理由人发起的调账（BR-WDR-23 末句，2026-11-21），追回只能经系统预填；W10 之后不会再有一次对账看到这几条账单行，所以放在 W10 同一事务里判 |

冻结不随 W10 或追回解除，照 BR-WDR-05 另行解除（现行）。

## 8. 2026-11-23 更正（编排自查，经 Gemini 独立核对发现）

§3 第 1 点原写「W10 的凭证与判定条件不变」，与 BR-WDR-15 细则「判成功的凭证交叉核对」②（D10-702：本单已有成功行而其通道单号与人填的不同 → 拒绝）相撞：②′ 的单本来就有两条不同通道单号的成功行，财务不管填哪一条，另一条都会触发拒绝，这张单将永远停在打款中。更正为：

1. 这种单 W10 只能判成功（PAID_API），不判 FAILED（已有成功行就是付过款的证据）。
2. 交叉核对 ② 改为「人填的通道单号是本单成功行之一即可，本单其余成功行不据此拒绝」；③ 只核人填那一行的金额。
3. 人填的那一行是主单的付款凭证；多付额 = 本单其余成功行金额之和（几条行金额不同也照此算），同一差错单只预填一张追回单（BR-FUND-24 ⑨）。

落点：08 BR-WDR-15 细则两处、BR-WDR-23 细则「确有多付」②；12 §5.6 注释。仍属编排的落实写法，负责人可推翻。B2-07h 写测前以此为准。
