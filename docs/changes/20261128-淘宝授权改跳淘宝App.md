# 2026-11-28 淘宝授权主路改跳淘宝 App（百川 SDK 授权，BR-ID-17 / BR-ID-18）

**类别**：00 §8 第 ② 类——改变用户授权边界（淘宝渠道备案授权主路改为客户端阿里百川 SDK Native 授权，网页授权回跳降为备用；新增阿里百川 SDK 授权能力接入；不改订单归属、资金口径、`bindings` 接口形状或对外承诺）。

**批准**：负责人 2026-11-28 在编排会话中明确指示：「要跳淘宝 App，在网页授权还有登录基本把用户拦截掉了，这个设计不合理，也不应该采取这种设计。」编排此前已说明跳淘宝 App 须接阿里百川 SDK（新增第三方能力），负责人该句即同意方向（编排裁定 D10-3704、D10-3709）。本规划 PR 由负责人合并。

> **能力验证前提**：**方向已定、能力未验证。** 生产环境对某一端下发 `sdk_token`，仍须 `CAP-TB-05` 实验 (f) 对该端实测通过并经负责人确认；未通过的端生产配置保持 `["web_code"]`。在 (f) 结论出来前，任何文档均不得把 `sdk_token` 授权能力写成对用户的承诺或已证实事实。

## 1. 变更内容与理由

- **内容**：调整淘宝渠道备案授权的主备路线——主路改为淘宝客户端百川 SDK Native 授权（装有淘宝 App 时跳淘宝 App 确认登录授权并回到凑狸继续购买，未装淘宝 App 时在 SDK 内完成登录），原网页授权回跳（`web_code`）保留为备用路径；生产配置 `union.taobao.auth_methods.<端>` 在 `CAP-TB-05` 实验 (f) 对某一端通过并经负责人确认后默认 `["sdk_token","web_code"]`，未通过的端保持 `["web_code"]`；SDK 授权所用的淘宝联盟应用公开标识由服务端随 `auth-url` 及 30101 / 30102 的 `data` 下发（可选公开字段 `sdk_app_key`，仅下发 `sdk_token` 时必带）。业务规则取值与细则只在 `规划/08_业务规则/10_ID_身份授权与合规.md` BR-ID-17、BR-ID-18 维护，本文不复述。
- **理由**：网页授权要求用户在系统浏览器内重新登录淘宝账号，对用户拦截率高、转化损耗大；根据百川官方文档存档（私有库 `docs-mirror/baichuan`、`docs-mirror/taobao/baichuan`）及淘宝联盟开放平台文档存档（私有库 `docs-mirror/taobao/aff-open-docs`），iOS / Android / 鸿蒙三端百川 SDK 均提供可显式传入 `appkey` 的官方 Native 授权接口，改为 SDK 授权主路可降低授权流失，同时保留 `web_code` 作初始化失败或上游拒绝时的降级与一键回退路径。
- **代价与前置**：
  - 须完成负责人侧阿里后台准备：核对已建的 iOS「凑狸」、Android「凑狸app」百川应用准入与「百川电商SDK」开通状态，新建鸿蒙百川应用（Bundle Name `com.couli.hm`）并提交加白，下载三端 V6 安全图片（安卓按签名生成，实验期先用测试签名，正式签名冻结后再生成正式安全图片），并在淘宝联盟开放平台上传授权浮层图标（操作步骤见调研方案 `couli-runs/TB-APP-AUTH/plan.md` A 节及编排发给负责人的 `owner-steps.md`；密钥与安全图片不进公开仓库）。
  - 关键待验证风险仍在 `CAP-TB-05` 实验 (f)：现有百川应用与淘宝联盟应用分属两个淘宝账号，传入联盟应用 AppKey 经百川 SDK 换得的令牌能否作为联盟应用用户会话完成 `publisher.info.save` 并取得与网页授权一致的 `relation_id`，须真机实测确认。

## 3. 受影响的页面与接口

- **页面**：
  - `AuthSheet`（购买触发授权）：按下发 `auth_methods` 顺序优先执行 `sdk_token`，失败或取消按 BR-ID-18 提示并给【仍去购买（无返利）】【重试】；SDK 授权页不得改写应用名和图标。
  - 授权管理页 `AuthManage`：【去授权】走同一套授权方式；页面仍只显示「已授权 / 未授权」，不显示淘宝账号名、昵称或头像。
- **接口与契约**：
  - `GET /v1/unions/{platform}/auth-url` 及错误码 30101 / 30102 的 `data`：新增可选公开字段 `sdk_app_key`（仅当 `auth_methods` 含 `sdk_token` 时必带，取值取自服务端 state 记录的淘宝联盟应用公开标识，不经客户端传入或改写）；对应代码仓库契约单 `CT-TBAPP`，具体字段形状以代码仓库 `contracts/` 为准。
  - `POST /v1/unions/{platform}/bindings` 与 `GET /v1/unions/bindings`：接口形状不变（`bindings` 已支持 `sdk_token` 分支 `{state, auth_method: "sdk_token", access_token, expires_in}`，只传凭证，不传昵称、头像、淘宝用户 ID）。
  - 数据库表结构：`union_auth_sessions`、`union_bindings`、`union_filing_attempts` 既有约束已允许 `sdk_token`，无数据库迁移。
- **生产放开约束**：在 `CAP-TB-05` 实验 (f) 对某端通过并经负责人确认前，服务端保留生产过滤，生产环境不签发、不接受该端的 `sdk_token`。

## 4. 验收要点

- **前置能力验证（`CAP-TB-05` 实验 (f)）**：先在 Android 正式包 staging 构建上以单一测试淘宝账号完成「SDK 授权备案 → 后台重置授权 → 网页授权备案」比对，确认令牌可调通 `publisher.info.save`、两种方式 `relation_id` 一致、记录 `expireTime` 格式，并完成跨应用 AppKey 反例；iOS 待取得 Team ID、鸿蒙待加白批下后各补测一次 SDK 授权。
- **规划验收用例（`规划/10_首个完整流程验收用例.md`）**：
  - `AC-S1-05-TB`：补充 `sdk_token` 不回跳、SDK 直接返回令牌后调 `bindings` 的断言；
  - `AC-S1-66`：既有自动化 fixture 暂不改值（待 (f) 出结果后按各端实际配置更新）；补充手工用例（装淘宝时跳淘宝 App 授权并回到凑狸继续购买；没装淘宝时在 SDK 内登录；SDK 返回取消按 BR-ID-18 处理），并注明各端 `sdk_token` 下发以 (f) 结果为准；
  - `AC-S1-102`：授权管理页断言不变，确认【去授权】走同一套授权方式。
- **服务端规则测试与评审**：按用户授权边界（RV2 / 资金与授权类评审强度）覆盖 `sdk_token` 原样作 session 不换码、令牌不落库不进日志、应用标识不符即拒、重复备案核对、生产环境拒签发与拒接受、同 state 并发提交互斥等场景。

## 5. 恢复方式

- 只需将生产配置 `union.taobao.auth_methods.<端>` 改回 `["web_code"]`（或由服务端生产过滤继续屏蔽 `sdk_token`），客户端即自动回到网页授权回跳路径；`web_code` 路径完整保留作备用，不涉及任何数据迁移或历史绑定兼容负担。
